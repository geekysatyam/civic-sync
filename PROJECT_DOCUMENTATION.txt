1) WHAT THE PROJECT IS
----------------------
CivicSync is a full-stack civic-tech web application that lets citizens
report local infrastructure issues, lets municipal leadership track and
resolve them with SLA accountability, and lets state admins monitor
cross-city trends and emergencies — with gamification, AI triage,
community-led resolutions, maps/heatmaps, and verifiable PDF certificates.


2) WHY THE PROJECT EXISTS
--------------------------
Common civic reporting failures:
- Complaints disappear with no public tracking or accountability.
- No SLA timers — departments face no deadline pressure.
- No structured citizen collaboration (volunteering, spot adoption).
- Hard to see hotspots/trends across neighborhoods and cities.

CivicSync goals:
- Make reporting easy, structured, and location-aware.
- Make accountability visible (status + SLA timer + breach alerts).
- Encourage community participation (drives, adopt-a-spot, karma rewards).
- Support governance with dashboards, heatmaps, and escalation tools.
- Add AI triage (Gemini) to improve signal-to-noise.


3) ROLES
--------
Citizen
  Reports issues, upvotes, participates in volunteer drives and polls,
  proposes community resolutions, earns karma/badges/rank, downloads
  verifiable PDF certificates.

Contractor
  Views issues under their trade category, updates work status,
  uploads before/after photos.

Department Head
  Manages issues for their department, updates status, broadcasts
  updates to upvoters, views department stats.

Mayor (Municipal dashboard)
  Acknowledges/assigns/resolves issues, uploads after-fix photos,
  broadcasts updates, manages contractors and dept heads, views
  city heatmap, SLA alerts, scorecard, predictive maintenance,
  CSR forwarding, ghost audit logs, city leaderboard.

State Admin
  Monitors all cities: statewide heatmap, city leaderboard, trend
  insights, emergency/red-alert feed, can ping mayors to escalate,
  moderates story articles, views contractor status across state.

Admin (Platform)
  User management, content moderation, platform-wide oversight.


4) FEATURES
-----------
Core issue reporting & tracking
  - Create issue with category, description, suggested solution, location.
  - Upload photos (before/after via Cloudinary).
  - Status lifecycle: pending → acknowledged → in_progress → resolved.
  - Accountability clock and SLA tracking with breach flags/alerts.
  - Red alert escalation for critical issues.

AI triage (Gemini 1.5 Flash + rule-based fallback)
  - 2-sentence LLM summary on issue creation.
  - Severity scoring (1–5).
  - Abuse/spam detection.
  - Translation detection + mayor-view translate button.
  - Priority score: severity×20 + upvotes×2 + SLA breach + red alert.
  - Recomputed every 6h via cron.

Citizen engagement
  - Upvotes and broadcasts.
  - Community resolution: citizen uploads fix photo, verifier approves.
  - Volunteer drives with pledges and scheduling.
  - Adopt-a-spot commitments.
  - Karma rewards/perks redemption.
  - Local polls (Nukkad) with geofencing.
  - Specialty badges (16 types) with unlock hints.
  - Rank progression: Civic Scout → Block Captain → Neighborhood Advocate
    → City Guardian → District Champion → State Legend.

Certificates
  - PDF certificate generated on demand via pdfkit.
  - QR code links to public /verify/:serial page.
  - Achievement title based on rank/hours/solutions.
  - Featured civic report section, mayor signature, seal.
  - Verifiable via public URL — no login required.

Maps & analytics
  - Citizen map views (Leaflet).
  - Mayor city heatmap (issue density by neighborhood).
  - State heatmap (cross-city hotspots).
  - Public city stats page /city/:slug/stats (no auth).
  - Resolution rate trend chart (6-month LineChart).
  - Anomaly spike detection (2× 7-day average).

Governance tools
  - Department scorecard with SLA compliance.
  - Predictive maintenance alerts.
  - Ghost audit scheduling (6 months post-resolution).
  - Immutable audit log (AuditLog collection).
  - Citizen issue history export (JSON).
  - Native Web Share on issue detail.

Notifications
  - In-app notification feed.
  - Email notifications via Resend (SLA breach, broadcasts, rank-up).


5) ARCHITECTURE
---------------
Frontend  →  React + TypeScript SPA (Vite) on Vercel
Backend   →  Node.js + Express (TypeScript, ESM) on Railway
Database  →  MongoDB Atlas (cloud)
Storage   →  Cloudinary (images)
Email     →  Resend
AI        →  Google Gemini 1.5 Flash

Request flow:
  Browser → Vercel CDN → React SPA
  React SPA → Axios (VITE_API_URL) → Railway Express API
  Express → MongoDB Atlas / Cloudinary / Resend / Gemini

Auth flow:
  Login → JWT access token (15m) returned in response body
        + refresh token in httpOnly cookie (7d)
  Axios interceptor attaches Bearer token to every request.
  On 401 → auto-refresh via /api/auth/refresh → retry original request.

Dev convenience:
  Vite dev server on :8080 proxies /api → http://127.0.0.1:5000
  so no CORS issues in local development.

9) RUNNING LOCALLY
------------------
Prerequisites
  Node.js ≥ 20.19.0
  MongoDB Atlas account (or local MongoDB)

Backend
  cd Backend
  npm install
  # create Backend/.env with variables from section 8
  npm run dev
  # → http://localhost:5000/api/health should return {"ok":true}

Frontend
  cd Frontend
  npm install
  # .env.local can be empty for local dev (Vite proxy handles /api)
  npm run dev
  # → http://localhost:8080

Seed demo data
  cd Backend
  npm run seed          # full seed (9 cities, all roles, issues, etc.)
  npm run seed:admin    # admin user only
  npm run seed:user     # citizen user only
  # See SEED_CREDENTIALS.md for login details

Build backend (TypeScript compile)
  cd Backend
  npm run build         # outputs to dist/
  npm run start         # runs dist/index.js

13) BACKGROUND JOBS (CRON)
--------------------------
All jobs start on server boot via startCronJobs() in src/jobs/cron.ts.
All jobs are wrapped in safe() — errors are logged, never crash the server.

Every hour (0 * * * *)
  SLA breach check: find acknowledged issues past slaDeadline,
  set slaBreached=true, email mayor, create sla_breach notification.

Every day at midnight (0 0 * * *)
  Ghost audit scheduling: find issues resolved 6+ months ago,
  assign to nearest City Guardian, create audit_ping notification.

Every month on 1st (0 0 1 * *)
  Reset Block Captain superVoteUsedAt,
  create super_vote_reset notification for all Block Captains.

Every 2 hours (0 */2 * * *)
  Red alert monitoring: find unacknowledged red alerts 2h+ old,
  set redAlertUnacknowledgedFlag=true,
  create escalation notification for all state admins.

Every 6 hours (0 */6 * * *)
  Priority score recompute: bulkWrite priorityScore for all open issues
  (severity×20 + upvotes×2 + slaBreached×30 + isRedAlert×50).


14) CERTIFICATE GENERATION
---------------------------
Endpoint:  GET /api/users/:id/certificates  (auth required)
Output:    PDF file download (application/pdf)

Process:
  1. upsertCertificate() — find or create Certificate record in DB.
     issuedAt is preserved on updates (not reset).
  2. Fetch avatar image buffer (converts DiceBear SVG URLs to PNG).
  3. Resolve logo.png from Frontend/public/ (multiple path candidates).
  4. Generate QR code PNG pointing to /verify/:serial.
  5. Build PDF with pdfkit — all drawing is synchronous.
  6. Collect PDF chunks into Buffer via 'data' event.
  7. Await 'end' event → send complete buffer with Content-Length header.
     (This prevents truncated PDFs — the key fix over the original pipe approach.)

PDF layout:
  Banner (NAVY, 110px tall):
    Row 1: Logo + "CivicSync" wordmark (left) | "GOVERNMENT OF PUNJAB" (right)
    Row 2: Achievement title (centered)
  Body: Avatar circle, seal, holder name, description, stat boxes,
        rank, badges, featured issue, QR code, signatures.

Verify page:  /verify/:serial  (public, no auth)
  Calls GET /api/certificates/verify/:serial
  Shows holder name, city, rank, hours, solutions, issued date.


15) SECURITY NOTES
------------------
Secrets
  - All secrets in environment variables only — never in code or git.
  - Backend/.env is in .gitignore (both Backend/.gitignore and root .gitignore).
  - JWT secrets are 64-byte hex — rotate immediately if exposed.

Authentication
  - Access tokens: JWT, 15-minute expiry, sent in Authorization header.
  - Refresh tokens: JWT, 7-day expiry, httpOnly cookie (sameSite=none, secure=true in prod).
  - All protected routes use authRequired middleware.
  - Role checks enforced server-side via roleGuard middleware.

CORS
  - Strict origin allowlist from CLIENT_URL env var.
  - Trailing slashes stripped before comparison.
  - Vercel preview deployments allowed via regex pattern.
  - Blocked origins logged to console for debugging.

Uploads
  - Multer limits: 8MB max file size.
  - Only image/* MIME types accepted.
  - Files stored in Cloudinary — never on disk in production.

Production flags
  - NODE_ENV=production enables secure cookies.
  - MOCK_OTP must NOT be set in production.
  - COOKIE_SECURE must NOT be false in production.


16) KNOWN ISSUES & DNS NOTE
----------------------------
Railway domain DNS propagation
  The domain civic-sync-production.up.railway.app may not resolve on
  some ISP DNS servers (particularly in Pakistan/India) due to slow
  propagation. This is not a code issue.

  Workaround for users: set DNS to 8.8.8.8 (Google) on their device
  or router. The domain resolves correctly on Google DNS.

  For router-level fix (affects all devices on network):
    Router admin → WAN/DNS settings → Primary: 8.8.8.8, Secondary: 8.8.4.4

logo.png on Railway
  The certificate service looks for Frontend/public/logo.png relative
  to the backend process. On Railway, the Backend/ folder is the root,
  so the logo may not be found and falls back to a gold flag mark.
  To fix: copy logo.png into Backend/public/ and add that path to
  the resolveLogoPng() candidates array in certificateService.ts.

Node version
  mongodb@7.2.0 requires Node ≥ 20.19.0. Railway defaults to Node 18.
  Fixed via Backend/.node-version (contains "20") and nixpacks.toml.
